Where the workflow could go next

Two bets that grow out of how you already work.

A standing review panel for every MR you open

Your swarm reviews already catch issues before merge. Running them in CI on every MR would make that the default rather than a step you remember.

  • Run pi -p with the review-swarm prompt in a GitLab job.
  • Post findings as a draft note you approve with /mr-review.

Success measure: fewer review rounds per MR before merge.
